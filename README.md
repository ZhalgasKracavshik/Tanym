# Tanym — персональный AI-наставник для школьников Казахстана

> Проект для **Future Minds Hackathon 2026**, трек **Social Impact**.
> «Таным» (қаз. *таным*) — познание.

Качественное образование в Казахстане распределено неравномерно: ученик в областном центре
может нанять репетитора, а ученик в ауле — нет. Учитель физически не успевает найти пробел
у каждого из тридцати человек в классе. Tanym решает это тем, что даёт каждому ученику
персональную траекторию, а учителю — карту пробелов всего класса.

**Ответ на вопрос кейса:** искусственный интеллект не заменяет учителя, а масштабирует
внимание к ученику. Система измеряет уровень по каждому навыку, сама подбирает следующий шаг
и объясняет каждую ошибку — столько раз, сколько нужно, и бесплатно.

## Что умеет MVP

| Обязательное требование кейса | Где реализовано |
| --- | --- |
| Главная страница с ценностным предложением | `/` |
| Профиль ученика: класс, предмет, цель | `/onboarding`, `/profile` |
| Диагностика уровня знаний | `/diagnostics/[subjectId]` |
| AI-модуль персонализации | `/plan` + `src/lib/personalization.ts` |
| Минимум 2–3 темы с заданиями | 3 предмета × 4 темы = 12 тем, 70+ заданий |
| Личный кабинет с прогрессом и слабыми местами | `/dashboard` |
| Панель учителя с добавлением тем | `/teacher` |
| Обратная связь по заданиям | `/learn/[topicId]` + `/api/ai/feedback` |

Дополнительно: AI-чат наставника (`/chat`), геймификация (очки за сложность заданий),
адаптивная сложность, мобильная вёрстка.

## Как здесь работает искусственный интеллект

Ключевое архитектурное решение: **ИИ разделён на два слоя**, и это разделение — главное,
что отличает Tanym от «обёртки вокруг чата».

### Слой 1. Движок персонализации — `src/lib/personalization.ts`

Детерминированный, объяснимый, работает без интернета. Он решает, **что** рекомендовать:

- **Модель ученика по навыкам.** Уровень считается не по темам, а по атомарным навыкам
  («теорема Виета», «закон Ома»). Оценка обновляется экспоненциальным скользящим средним,
  где вклад попытки зависит от сложности задания: верный ответ на сложное — сильное
  доказательство знания, ошибка в олимпиадной задаче почти не роняет оценку.
- **Ранжирование тем.** Приоритет = 0.45 × пробел + 0.2 × готовность (пройдены ли
  темы-предпосылки) + 0.2 × соответствие цели + 0.15 × незавершённость. Веса собраны
  в одном месте и подписаны.
- **Адаптивная сложность.** Скользящее окно из 4 последних попыток: ≥75% верных — уровень
  вверх, ≤25% — вниз.

Каждая рекомендация возвращает не только число, но и **причины** человеческим языком
(«Слабое место: тема освоена на 32%»). Их видит ученик, и они же уходят в языковую модель.

### Слой 2. Языковая модель — Google Gemini

Отвечает за то, **почему** и **как объяснить**. Модель не считает статистику и не решает
задачи заново: она получает готовые цифры из движка и эталонное решение из контента,
и переводит это в человеческую речь. Поэтому объяснение никогда не расходится с тем,
что ученик видит на экране.

Три сценария:

| Эндпоинт | Что делает |
| --- | --- |
| `POST /api/ai/feedback` | Разбирает ответ на задание: называет ошибку, объясняет верный ход |
| `POST /api/ai/plan` | Объясняет персональный план: что показала диагностика и с чего начать |
| `POST /api/ai/chat` | Отвечает на вопросы ученика по теме, не выдавая готовых решений ДЗ |

**Надёжность.** У каждого сценария есть детерминированный дублёр (`src/lib/ai/fallback.ts`).
Если API недоступен, перегружен или закончилась квота — ученик всё равно получает разбор,
собранный из эталонного решения. Интерфейс честно помечает это меткой «Разбор без AI»
вместо «Ответ AI»: подменять модель заготовкой молча — обман пользователя.
Дополнительно работает цепочка запасных моделей: при проверке `gemini-3.7-flash` вернула 503,
и запрос автоматически ушёл на `gemini-3.5-flash`.

**Безопасность ключа.** Ключ живёт только в переменной окружения на сервере. Страницы
обращаются к собственным роутам `/api/ai/*`, и оттуда уже идёт запрос в Google. Если бы
модель вызывалась прямо из компонента, ключ попал бы в браузерный бандл.

## Технологический стек

| Слой | Технология | Почему так |
| --- | --- | --- |
| Фронтенд | Next.js 16 (App Router), React 19, TypeScript strict | Один проект на страницы и API, строгая типизация контента |
| Стили | Tailwind CSS v4 | Дизайн-токены в `globals.css`, без разъезжающихся стилей |
| ИИ | Google Gemini API (REST, без SDK) | Бесплатная квота, виден точный HTTP-запрос |
| Данные ученика | localStorage | Кейс допускает mock-хранилище; структура готова к переносу в БД |
| Учебный контент | Типизированные TS-модули | Контент проверяется компилятором и версионируется вместе с кодом |
| Хостинг | Vercel | Нулевая настройка для Next.js |

```
│   ├── types.ts                    Доменные типы — контракт всего приложения

│       ├── prompts.ts              Сборка промптов
│       ├── fallback.ts             Ответы без модели
│       ├── contracts.ts            Общие типы запросов клиент ↔ сервер
│       └── rate-limit.ts           Ограничение частоты запросов
├── data/
│   ├── index.ts                    Реестр контента и функции поиска
│   ├── subjects/                   Математика, физика, история Казахстана
│   └── demo-class.ts               Детерминированный класс для панели учителя
└── components/
    ├── StoreProvider.tsx           Состояние ученика на React Context
    ├── SiteHeader.tsx              Навигация
    ├── AiBadge.tsx                 Метка «Ответ AI» / «Разбор без AI»
    └── ui/index.tsx                UI-кит
```

**Поток данных при ответе на задание:**

```
Ученик отвечает
   → POST /api/ai/feedback { taskId, answer, ... }
   → сервер находит задание в реестре и САМ проверяет ответ
     (клиенту нельзя доверять оценку правильности)
   → промпт с эталонным решением → Gemini
   → ответ + метка live/fallback
   → recordAttempt() обновляет навык, прогресс темы, очки и уровень сложности
   → изменения сразу видны в /dashboard, /plan и в панели учителя
```

## Запуск

Нужен Node.js 20 или новее.

```bash
git clone <адрес репозитория>
cd Tanym
npm install
```

Получите бесплатный ключ в [Google AI Studio](https://aistudio.google.com/apikey),
скопируйте `.env.example` в `.env.local` и вставьте его:

```bash
cp .env.example .env.local
```

Проверьте, что ключ работает:

```bash
node scripts/check-ai.mjs
```

Запустите:

```bash
npm run dev
```

Откройте http://localhost:3000

> Без ключа приложение **тоже работает**: все экраны, движок персонализации, диагностика
> и задания функционируют, а вместо ответов модели показываются готовые разборы с пометкой
> «Разбор без AI».

## Что здесь настоящее, а что тестовое

Честный список — по требованию кейса («что является тестовыми данными»).

**Работает по-настоящему:**
- движок персонализации: расчёт навыков, ранжирование тем, адаптация сложности;
- проверка ответов и подсчёт прогресса;
- запросы к Google Gemini и разбор ошибок живой моделью;
- сохранение состояния между сессиями;
- добавление тем учителем — созданная тема сразу открывается и решается.

**Тестовое (mock) в этой версии:**
- **Класс в панели учителя** генерируется детерминированно из имён и реального контента
  (`src/data/demo-class.ts`): в MVP нет общего сервера, где хранились бы данные разных
  учеников. Прогресс реального пользователя при этом подмешивается в таблицу отдельной
  строкой — видно, как действия ученика доходят до учителя.
- **Вход без пароля**: роль выбирается при онбординге. Настоящей авторизации нет.
- **Хранилище** — браузер, а не база данных. Один браузер = один ученик.
- **Контент** — 3 предмета по 4 темы. Это демонстрационный объём, а не полная программа.

## Использование AI-инструментов при разработке

В соответствии с частью 8 положения хакатона: AI-инструменты применялись как
вспомогательные при написании кода. Архитектурные решения — разделение движка
персонализации и языковой модели, серверная проверка ответов, механика запасных
ответов, модель навыков вместо модели тем — приняты и могут быть объяснены авторами.
