# Достижения и прогресс: новая логика

Статус: **спроектировано, не реализовано.** На пилоте раздел скрыт (`/achievements` и `/leaderboard` в `src/lib/pilot.ts`). Документ основан на вердикте совета от 2026-10-06 (`docs/council/council-report-2026-10-06.html`).

## Почему старая логика не подходит

| Что было | Проблема |
| --- | --- |
| Ученик загружает скан грамоты, админ ставит баллы по уровню и месту | Это персональные данные ребёнка (имя, школа, класс). Сканы легко подделать, а проверка целиком ложится на одного админа. |
| Общий рейтинг школы и «место #7» | Новичок с нулём баллов видит себя внизу списка. Это отталкивает, а не мотивирует. При малой аудитории рейтинг пустой. |
| Уровни «Бронза…» и баллы за решённые темы | Привязаны к учебному модулю, который на пилоте выключен. Ученик не понимает, что они значат. |
| Дневная серия | Дедлайны бывают раз в несколько недель. Ежедневной серии не на чем держаться. |

## Новая модель

### 1. Портфолио, привязанное к афише

Запись портфолио создаётся из события, которое ученик сохранил в «Мои события». Ничего не нужно вписывать заново.

```
сохранил ──► подал заявку ──► участвовал ──► результат
 (event_saves)   (отметка)      (отметка)      (место / диплом / участие)
```

- Статусы ставит сам ученик одной кнопкой на странице события. Это его личная история, без баллов и без чужих глаз.
- **Подтверждение без скана:** ссылка на опубликованный список победителей организатора (http/https, проверяется как `registration_url`) или отметка учителя, который ведёт ученика. Скан не храним.
- **По умолчанию приватно.** Публичная карточка «Мои достижения» включается отдельно и вручную. Карточку можно отправить по ссылке для поступления, грантов, НИШ.
- Таблица: `portfolio_entries(user_id, event_id null, title, status, result, proof_url null, verified_by null, is_public default false, created_at)`. RLS: читает и пишет владелец; публичные записи доступны по ссылке; `verified_by` ставит только учитель или админ.

### 2. Сезонный личный прогресс вместо общего рейтинга

- **Сезон = учебная четверть.** Счёт обнуляется: новичок, пришедший в середине года, не отстаёт навсегда.
- Что засчитывается — только действия, которые ведут к цели пилота:
  - заявка, поданная **до** дедлайна (статус «подал» раньше `registration_deadline`);
  - решённое задание из архива (ответ проверяет сервер, как сейчас в `/api/ai/socratic`);
  - **недельная** серия: хотя бы одно действие за неделю.
- Показывается как личная полоса «3 недели подряд · 2 заявки в этой четверти», без места среди других.

### 3. Лидерборд — только по согласию и при достаточной аудитории

- Лидерборд класса или школы включается, когда в школе 15 и более активных учеников, и только для тех, кто дал согласие (`leaderboard_opt_in`, по умолчанию выключено).
- Анонимный режим остаётся. Уровни «Бронза…» убираются.

## Порядок внедрения (после пилота)

1. Статусы «подал / участвовал» на странице события. Это меньшая работа и сразу полезная метрика для пилота: сколько заявок подано благодаря афише.
2. `portfolio_entries` + приватная страница «Моё портфолио».
3. Публичная карточка по ссылке.
4. Сезонный прогресс на «Моём пути».
5. Лидерборд — только при выполнении порогов.

## Ограничения

- Закон РК о персональных данных (№94-V): нужно согласие законного представителя на обработку данных несовершеннолетнего. Перед ростом нужна консультация юриста по локализации данных: Supabase хранит их за рубежом. Собираем минимум: почту, класс и интересы. Сканы не собираем.
- Старые таблицы (`portfolio_achievements`, `achievement_posts`, бакеты `achievement-proofs` и `achievement-photos`) не удаляются, пока не решено, переносить ли записи. Скан-бакет уже приватный (`pilot_storage_hardening`).
