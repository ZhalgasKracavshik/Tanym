# React и архитектура Tanym: что нужно понимать на защите

Только то, что реально есть в этом проекте. Ничего лишнего.

---

## 1. Что такое компонент

Компонент это функция, которая возвращает разметку.

```tsx
function Badge({ text }) {
  return <span className="rounded-full">{text}</span>;
}
```

Используется как тег: `<Badge text="Слабое место" />`.

**Props** это входные данные компонента (здесь `text`). Односторонние: родитель передаёт
ребёнку, обратно нет.

**Если спросят «зачем компоненты»:** карточка выбора на онбординге используется на трёх
шагах, это роль, предметы и цель. Вместо трёх копий разметки один `ChoiceCard`
(`src/app/onboarding/page.tsx`, функция объявлена внизу файла).

---

## 2. useState: память компонента

```tsx
const [step, setStep] = useState(1);
```

- `step` текущее значение
- `setStep` функция изменения
- `1` начальное значение

Главное правило: **`step = 2` не работает**, нужно `setStep(2)`. Потому что React должен
узнать об изменении, чтобы перерисовать экран. Прямое присваивание он не увидит.

**Где в проекте:** `src/app/onboarding/page.tsx`, там семь таких ячеек подряд: шаг мастера,
имя, роль, класс, предметы, цель, дата экзамена.

---

## 3. useEffect: «сделать что-то после отрисовки»

```tsx
useEffect(() => {
  setState(loadState());
  setHydrated(true);
}, []);
```

Второй аргумент это список зависимостей:
- `[]` выполнить один раз при появлении компонента
- `[hydrated, topicId, session]` выполнять заново, когда меняется что-то из списка

**Зачем он нам:** `localStorage` существует только в браузере. Next.js сначала рисует
страницу на сервере, где его нет. Читать хранилище можно только после того, как страница
попала в браузер, это и есть `useEffect`.

**Где:** `src/components/StoreProvider.tsx`, там три эффекта: загрузка при первом заходе,
подписка на изменения из других вкладок, сохранение при любом изменении.

**Флаг `hydrated`:** пока данные не подняты из хранилища, страницы показывают скелет
(`<Skeleton />`), а не пустое состояние. Иначе на долю секунды мелькало бы «нет данных»
и сразу после этого реальные цифры.

## 4. `'use client'`: самая частая тема вопросов

Next.js по умолчанию рисует страницы **на сервере**. Там нет ни кликов, ни `useState`,
ни `localStorage`. Строка `'use client'` в начале файла говорит: «этот файл нужно
выполнять в браузере».

В Tanym почти всё клиентское, и это осознанно: каждый экран либо читает прогресс ученика,
либо переключает язык интерфейса, а и то и другое живёт в браузере.

| Серверные файлы | Клиентские файлы |
| --- | --- |
| `src/app/layout.tsx` (каркас, шрифт, метаданные) | 13 из 16 файлов `page.tsx`, включая лендинг |
| три тонкие обёртки динамических маршрутов | `src/components/StoreProvider.tsx`, `AiBadge.tsx` |
| все роуты `src/app/api/ai/*/route.ts` | `LearnClient`, `MaterialClient`, `DiagnosticsClient` |

**Если спросят про лендинг:** он тоже клиентский, хотя разметка статическая. Причина в том,
что подписи берутся по текущему языку через хук `useLang()`, а хуки работают только
в браузере. Честный ответ: за трёхъязычный интерфейс мы заплатили тем, что лендинг не
отдаётся готовым HTML.

**Что осталось серверным и почему это важно:** роуты `src/app/api/ai/*`. Именно там лежит
ключ Gemini и проверка ответов. Всё, что попадает в клиентский файл, видно любому через
исходники страницы.

## 5. Зачем у динамических страниц два файла

Адрес `/learn/math.linear` содержит переменную часть. Next.js 16 отдаёт её через `params`,
и это **промис**, значит компонент должен быть `async`. Но клиентский компонент `async`
быть не может.

Отсюда два файла:

```tsx
// src/app/learn/[topicId]/page.tsx: серверный, разворачивает промис
import { LearnClient } from './LearnClient';

export default async function LearnPage({ params }: PageProps<'/learn/[topicId]'>) {
  const { topicId } = await params;
  return <LearnClient topicId={topicId} />;
}
```

```tsx
// src/app/learn/[topicId]/LearnClient.tsx: клиентский, вся логика
'use client';
export function LearnClient({ topicId }: { topicId: string }) { ... }
```

Такая пара есть трижды: `learn/[topicId]`, `archive/[materialId]`, `diagnostics/[subjectId]`.
Серверный файл в каждой паре занимает пять строк.

## 6. Как данные ходят по приложению

```
StoreProvider (одно хранилище на всё приложение)
      │  useStore()
      ├──► /plan          читает прогресс → показывает рекомендации
      ├──► /learn         записывает попытку → recordAttempt()
      ├──► /dashboard     читает → показывает статистику
      ├──► /achievements  читает → считает достижения и серию дней
      ├──► /leaderboard   читает очки → ставит ученика в рейтинг
      ├──► /events        хранит регистрации на события
      ├──► /announcements хранит, что уже прочитано
      ├──► /marketplace   хранит объявления, поданные учеником
      └──► /teacher       читает → показывает ученика в таблице класса
                    │
                    ▼
              localStorage (переживает перезагрузку)
```

`useStore()` это способ достать хранилище в любом компоненте без передачи через props
по цепочке. Один источник данных, поэтому цифры в кабинете, плане, рейтинге и панели
учителя всегда совпадают.

## 7. Что происходит при ответе на задание

Этот путь стоит рассказать на защите целиком, он показывает всю архитектуру.

```
1. Ученик выбирает вариант             → setAnswer('2')
2. Нажимает «Ответить»                 → fetch('/api/ai/feedback')
3. СЕРВЕР находит задание в реестре и САМ проверяет ответ (checkAnswer)
4. Собирает промпт: условие + эталонное решение + уровень ученика
5. Отправляет в Gemini, ключ не покидает сервер
6. Возвращает { correct, correctAnswer, text, live }
7. recordAttempt() обновляет навык, прогресс, очки, серию дней, сложность
8. Изменения видны в кабинете, плане, рейтинге и у учителя
```

**Вопрос, который зададут: почему проверяет сервер, а не браузер?**
Если бы вердикт присылал клиент, достаточно было бы подделать одно поле в запросе,
чтобы получить «верно» на что угодно.

**Второй вопрос: почему не звать Gemini прямо из браузера?**
Всё, что попадает в код страницы, видно любому через исходники. Ключ утёк бы сразу.

## 8. Разделение ИИ на два слоя: главный тезис

```
Движок (src/lib/personalization.ts)     Модель (Gemini)
детерминированный, без интернета        языковая

решает ЧТО рекомендовать        →       решает КАК объяснить
• уровень по навыкам                    • разбор ошибки
• ранжирование тем                      • объяснение плана
• адаптация сложности                   • ответы наставника
                                        • вопросы по методу Сократа

    передаёт готовые цифры и причины ──────►
```

Формулировка для питча:

> «Модель не считает статистику и не решает задачи заново. Она получает готовые цифры
> из движка и эталонное решение из контента. Поэтому объяснение никогда не расходится
> с тем, что ученик видит на экране».

## 9. Свои иконки вместо эмодзи

Во всём интерфейсе нет ни одного эмодзи. Вместо них компонент `Icon`
(`src/components/Icon.tsx`, 45 иконок).

**Почему не эмодзи.** Эмодзи рисует шрифт операционной системы. На Windows, Android
и iPhone одна и та же ракета выглядит по-разному, эмодзи не подчиняется цвету текста
и сбивает высоту строки. Для продукта, который открывают с любого телефона, это значит,
что разные ученики видят разный интерфейс.

**Как устроен компонент.** Одна функция, два props:

```tsx
<Icon name="medal" size={14} />
```

- `name` берётся из типа `IconName`, это список из 45 разрешённых имён. Опечатку
  `"medall"` TypeScript не пропустит на этапе сборки, вместо пустого места в интерфейсе
  будет ошибка компиляции.
- Внутри лежит объект `PATHS`, где каждому имени соответствует набор фигур SVG.
  Все нарисованы в квадрате 24 на 24, контуром одной толщины, без заливки, поэтому
  в строке смотрятся как одно семейство.
- Цвет задан как `stroke="currentColor"`. Это значит «взять цвет текста родителя»:
  иконка автоматически совпадает по цвету с подписью рядом и не требует отдельной
  настройки под каждый фон.
- `aria-hidden="true"` скрывает иконку от программ чтения с экрана, потому что рядом
  всегда есть текстовая подпись. Иначе незрячий пользователь слышал бы название картинки
  и следом то же самое словами.

**Если спросят, почему не библиотека иконок:** в проекте ноль UI-зависимостей.
Свой набор весит несколько килобайт и рисуется ровно в том стиле, что и всё остальное.

## 10. Модули поверх учебного ядра

Пять экранов, которые не относятся к циклу «диагностика, план, тема», но закрывают
реальные разрывы школьной жизни.

| Модуль | Что делает | Где лежит |
| --- | --- | --- |
| Архив (`/archive`) | 6 материалов ЕНТ, олимпиад, IELTS, SAT и ТЖБ/БЖБ, 18 заданий. Задание разбирается в диалоге по методу Сократа: наставник задаёт вопросы и не называет ответ. Вариантов ответа нет намеренно, иначе ученик угадывал бы вместо рассуждения. | `src/app/archive/`, логика `src/lib/archive.ts`, распознавание ответа `src/lib/archive-answer.ts`, контент `src/data/archive.ts` |
| Афиша (`/events`) | 9 событий: олимпиады, конкурсы, школьные мероприятия, вебинары. Главное на экране не список, а срок: дедлайн вынесен в заметное место, события с закрывающейся регистрацией поднимаются наверх. | `src/app/events/page.tsx`, `src/lib/events.ts`, `src/data/events.ts` |
| Возможности (`/marketplace`) | 11 объявлений: секции, курсы учителей, услуги учеников, внешние центры. Бесплатное и проверенное школой стоит выше платного. Объявление от пользователя помечается как ожидающее проверки. | `src/app/marketplace/page.tsx` и `PublishForm.tsx`, `src/lib/listings.ts`, `src/data/listings.ts` |
| Объявления (`/announcements`) | 8 объявлений администрации с адресатом по классу, сроком жизни и приоритетом. Замена рассылке в мессенджере: закреплённое сверху, истёкшее приглушено, непрочитанное помечено. | `src/app/announcements/page.tsx`, `src/lib/announcements.ts`, `src/data/announcements.ts` |
| Рейтинг (`/leaderboard`) | 14 участников, очки за решённые задания. Ключевое решение это режим анонимности: имя заменяется псевдонимом, но очки продолжают считаться и из рейтинга ученик не выпадает. Переключатель стоит прямо на экране, а не в дальних настройках. | `src/app/leaderboard/page.tsx`, `src/lib/leaderboard.ts`, `src/data/leaderboard.ts` |

Общий приём во всех пяти: файл в `src/lib/` содержит типы и правила (сортировка, статус,
сроки), файл в `src/data/` содержит сам контент, страница в `src/app/` только показывает.
Поэтому контент можно заменить на данные из базы, не трогая экран.

## 11. Что спросят про надёжность

Самый вероятный вопрос жюри: «вы это сами тестировали или оно просто скомпилировалось».
Ниже четыре реальных дефекта, которые нашёл аудит кода, и как они звучат своими словами.
Их полезно назвать самим, до вопроса.

### 11.1. Клиент не проверял, что сервер вообще ответил

**Что было.** Страница отправляла ответ на сервер и сразу разбирала ответ как результат
проверки. Но у сервера есть ограничитель частоты: 20 запросов в минуту. На двадцать первом
он отвечает не результатом, а отказом с кодом 429. Страница читала этот отказ, не находила
в нём поля `correct`, получала «пусто» и трактовала это как «неверно».

**Чем это плохо.** В прогресс ученика записывалась неверная попытка по заданию, которое
сервер даже не смотрел. Уровень навыка падал ни за что, и следующие задания становились
проще, чем нужно.

**Как исправлено.** Одна строка перед разбором ответа:

```tsx
if (!response.ok) throw new Error(`HTTP ${response.status}`);
```

Дальше срабатывает `catch`, страница показывает «не удалось связаться с сервером»
и **не выносит вердикт вообще**. Ничего в прогресс не пишется.

**Где смотреть:** `LearnClient.tsx`, `MaterialClient.tsx`, `src/app/chat/page.tsx`,
`src/app/plan/page.tsx`, во всех четырёх одинаково.

### 11.2. Подборка заданий пересчитывалась после каждого ответа

**Что было.** Список заданий темы собирала функция `selectTasks` прямо в теле компонента.
React вызывает тело компонента заново при любом изменении состояния, то есть после каждого
ответа. А `selectTasks` учитывает прогресс: решённые задания она уводит в конец списка.

**Чем это плохо.** Ученик отвечал верно, задание тут же переезжало в конец, и на экране
рядом с разбором его ответа оказывалось условие уже следующего задания. По кнопке «дальше»
одно задание пропускалось нерешённым.

**Как исправлено.** Подборка теперь живёт в состоянии и пересобирается только при смене
темы или при новом заходе:

```tsx
const [sessionTasks, setSessionTasks] = useState<Task[]>([]);
const [session, setSession] = useState(0);

useEffect(() => {
  setSessionTasks(selectTasks(topic, difficulty, state));
}, [hydrated, topicId, session]);
```

Кнопка «решить ещё раз» делает `setSession(value => value + 1)`, и только тогда собирается
новый список, уже с учётом изменившейся сложности. Формулировка для защиты: перетасовывать
задания под пальцем у ученика это плохая идея, изменения применяются со следующего захода.

### 11.3. Две вкладки затирали прогресс друг друга

**Что было.** Состояние пишется в `localStorage` целиком, одним ключом. Ученик открывал
две вкладки, решал задания в первой, потом нажимал что-нибудь во второй. Вторая вкладка
держала в памяти старый снимок и записывала его поверх, унося весь прогресс из первой.

**Как исправлено.** Браузер умеет сообщать вкладкам, что общий ключ изменили. Подписка
на это событие в `StoreProvider.tsx`:

```tsx
window.addEventListener('storage', handleExternalChange);
```

Событие `storage` приходит только в **другие** вкладки, поэтому бесконечного цикла нет:
вкладка, которая записала, себе уведомление не получает.

### 11.4. Односимвольные ответы в архиве засчитывались случайно

**Что было.** В архиве ученик пишет ход мысли обычным текстом, и код должен понять,
назвал он правильный ответ или нет. Первая проверка была наивной: «встречается ли нужное
число в сообщении».

**Чем это плохо.** Если ответ задачи равен единице, то фраза «у меня 1 вопрос: что делать»
засчитывалась как решение. Тот же эффект давало любое число из условия: в задаче про
подъём тела ответ 20 метров, но 20 есть и в условии (начальная скорость 20 м/с), и пересказ
условия открывал ученику готовый разбор.

**Как исправлено** (`src/lib/archive-answer.ts`, три правила):

1. Если число ответа встречается ещё и в условии, или если ответ это маленькое целое
   до десяти, одного упоминания мало. Нужен явный признак ответа.
2. Признаком считается слово-маркер («ответ», «получается», «жауап», «equals», знак `=`)
   в тридцати символах **перед** числом, а не где угодно в сообщении. Иначе во фразе
   «скорость 20 м/с, а g равно 10» маркер от десятки засчитывал бы двадцатку.
3. Либо сообщение состоит **только** из числа и короткой единицы измерения, причём
   обязано с этого числа начинаться.

Отдельно отсеиваются коэффициенты: в «получилось 5y = 10» пятёрка это множитель при
переменной, а не итог. И отдельно случай IELTS: если ученик перечислил сразу
True, False и Not Given, это цитата вариантов, а не ответ.

**Проверка:** `npm run test:answers`, 23 случая.
